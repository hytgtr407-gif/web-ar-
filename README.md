## 手机端加载

- 先显示页面内容，再按顺序加载 A-Frame 和 MindAR；两个库均固定版本，jsDelivr 下载失败/超时后切换 unpkg。
- 下载脚本最多等待每个地址 15 秒，完成下载后才执行，防止超时的旧请求晚到后重复注册。
- 目标文件使用项目相对路径预加载一次，检查 HTTP 状态与空文件，45 秒超时；通过 Blob URL 交给 MindAR，不再重复下载原文件。
- 两个库注册后才创建 A-Frame 场景。点击“启动相机”后才申请相机权限。
- 相机视频位于页面背景之上，透明 AR 画布位于视频之上，避免负 z-index 被背景遮挡。
- 降低移动端渲染负担，禁用抗锯齿和默认全屏加载层。资源失败、相机失败、初始化错误、60 秒启动超时或 WebGL 中断均显示提示和重试按钮。
- 捕获 MindAR 1.2.5 `_startAR` 的异步初始化错误并处理超时后的迟到相机结果；升级 MindAR 时需要复核此版本适配。
- 切换后台时暂停处理，离开页面时释放相机。通过浏览器返回缓存恢复时重新加载。

旧入口 `index_v3_AR_logging.html` 跳转至同一 `index.html`，保留查询参数，避免旧入口继续使用错位映射。
`assets/data/scene.json` 在准备阶段通过项目相对路径加载，15 秒超时。

## Semantic Gate

页面已实现原型级语义门控：`targetFound → targetIndex → 角色 ID → scene.json → 校验 → 展示/拦截`。内容标题、说明和 AR 图层由同一次校验共同控制。

`G = audited ∧ version_matched ∧ resource_valid`，每个字段都必须严格等于 JSON 布尔值 `true`。缺失、`false`、`null`、字符串或数字都不能放行。还需确认记录 ID、索引、标题和目标文件与已验证映射一致，且说明文本有效。内容使用 `textContent` 展示。

相机识别与内容放行分开处理。校验失败时保留“识别成功”状态，显示“内容暂未开放”及原因，不展示文化说明，隐藏相应 AR 内容层。JSON 下载失败、超时或格式错误也会拦截展示，但允许启动相机。`targetLost` 隐藏内容并提示重新放卡，重新识别时再次校验。切换卡片时先隐藏旧图层；前一个目标的迟到丢失事件不会清空新目标内容。

CSV 保留 `target_found` / `target_lost`，增加 `semantic_gate_pass` / `semantic_gate_block` 和 `reason` 列；元数据不可用另记 `semantic_metadata_error`。调试层显示门控状态与原因。

**当前三张卡仍为 `audited=false`，正式数据会拦截展示。** 测试中的放行数据是独立 fixture，不修改正式审核状态。完成真实内容审核后才更新对应字段。

该机制执行声明式校验状态，不自动开展文化事实审核、版本比对或资源完整性检测。它支持提高文化内容传递的可靠性，不保证文化真实性；审核来源、版本定义和字段维护仍需建立流程。

论文架构图、图注和实验边界见 `docs/semantic-gate-architecture.svg` 与 `docs/semantic-gate-paper-notes.md`。此前的 132.5 ms 为桌面模拟视频识别延迟（30 次均值，版本 ab05d29），不包括本次门控，也不是手机测量或整条内容展示链路延迟。

## 新一轮体验入口与操作说明（2026-10-04）

明天的新问卷应使用 `study.html`，而非正式门控入口 `index.html`。正式页增加明确研究体验入口，两页共用新的手机布局：用途、四步操作、卡片获取、识别状态、内容状态和本地日志。启动后收起步骤并减小面板占用，人物介绍可在面板内上下滑动。卡片移出时隐藏介绍与来源；重新识别后重新呈现。

`cards.html` 提供已有三张卡图，供另一块屏幕展示或打印。不要用同一部手机同时显示卡片并尝试用其摄像头扫描。

默认使用 B 界面；研究者可用 `study.html?ui=A` 访问简短动态提示条件，两条件共用用途说明、内容、门控、布局与来源。A 是本次固定的简短提示条件，不等同于原112人使用的旧正式拦截界面。`ui` 查询参数只能影响提示，不能打开正式页面的研究展示例外。

日志增加 `ui_variant`、`interface_version`；`elapsed_ms` 使用单调时钟，记录从本次页面会话开始的时间，不是目标进入镜头到识别的延迟。记录编号可与问卷人工对应，导出文件名包含内容版本、界面条件和匿名会话编号。识别计数不是阅读完成证明。

旧112份问卷据组织者说明对应正式拦截页；本次数据另存，不直接把旧答卷作为新A组。新问卷需修复Q2完整选项、Q11互斥逻辑，并按研究草稿实际提示校准Q10。发布材料与测试边界见 [`docs/ui-v2-study.md`](docs/ui-v2-study.md)。

## 检查与手机复测

需要 Node.js 18+，无需安装依赖：

```sh
node --check assets/app.js
node --test tests/ar.test.cjs
```

29 项回归测试使用模拟的相机/场景事件，覆盖三角色、真实组件索引、日志、Pages 子路径、CDN 回退、下载失败、初始化失败、超时、调试开关、相机启动防重入、严格门控、研究展示隔离，以及B界面的来源清理、恢复、状态解释、版本与日志记录。
目标文件哈希检查防止重新编译后继续沿用旧映射。若替换 `.mind`，先从内部追踪图像或实体卡片实测重新确认顺序，再更新映射与测试哈希。

手机复测：

1. 等待 GitHub Pages 发布该提交，然后重新加载 HTTPS 页面；iOS 用 Safari、Android 用 Chrome 打开。
2. 点击“启动相机”，允许相机权限，等待“相机已就绪”。
3. 分别扫描边一笑、崔云龙、张岫玉，确认调试索引为 0、1、2，角色与卡面一致。当前未审核数据应显示“内容尚未审核”，并隐藏 AR 内容层；审核完成后才验证正式内容放行。
4. 移开卡片再放回，导出 CSV，确认同一卡片的 `target_found` 和 `target_lost` 的 ID 与索引一致。
5. 在拒绝相机权限、弱网或相机被占用时确认错误提示可见；调整后点击重试。

浏览器界面检查和模拟事件不能代替 iOS/Android 真机识别与相机权限验证。
